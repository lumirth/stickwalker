# Fixed IR transport rebuild, 2026-10-30

This rebuild replaces the Stick-specific receiver and acquisition lifecycle while retaining the native Pokéwalker protocol and completion behavior. It introduces no calibration screen, training exchange, learned baud rate, saved sensitivity, or per-unit receiver setting.

## Provenance and deletion boundary

The starting StickWalker revision was [`3e6634d19201d2f58507af2d0c479a41b79ad533`](https://github.com/lumirth/stickwalker/commit/3e6634d19201d2f58507af2d0c479a41b79ad533). Its history begins with the [Pokéwalker reconstruction](https://github.com/lumirth/pw/tree/6dc7bc09950078fa3fe0dffa4dae34e9549a99da), followed by [`d7025f3`, the start of the Stick port](https://github.com/lumirth/stickwalker/commit/d7025f30e74a01d57494cd043556077dac534ef4). The native dispatcher, command actions, transfer completion, and save semantics were checked against that provenance. The HGSS reconstruction reference is [`pokeheartgold` at `8cbb4a1`](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/8cbb4a19ab781611ff1767035dcaea6b47baeded/src/application/pokewalker/pokewalker_ir.c).

Deleted Stick-specific mechanisms include packet-wide timing/length fitting, learned timing, the absolute activity cutoff, weak-bit repair, checksum-guided prefix realignment, the optical event queue, raw-event copies, implicit receive restart, and segmented receive ownership. The old private-bench scripts `port_hgss_trial.py` and `qualify_port_cycle.py` were removed. Storage's separate per-append deadline was removed; the transport now owns the complete request-to-reply deadline.

The receiver implementation and header shrink from 305 to 222 lines. The transport implementation shrinks from 817 to 556 lines. Across the 13 changed production C/C++ files, the total shrinks from 4,209 to 3,936 lines. Additional verification code models independent optical input, GDMA hardware, and complete native workflows.

The changed shared IR source preprocesses identically to the starting revision for the original H8 target, SHA-256 `bba2d2580bc59d69e8d6ae9ad65ce3f42345fd242ee666add67ff4017608fc79`. Comparison with `pw` found only three preexisting redundant macro parentheses. The proprietary Renesas 6.02.01/6.02.02 compilers were unavailable, so binary matching under those compilers was not rerun.

The port's existing target-specific exclusions remain: H8 RAM-write diagnostics are rejected on ESP32, where those addresses do not describe the same memory. The original H8 handler remains unchanged.

## Replacement architecture

Core 0 continuously publishes raw gates at 345,600 Hz into a 32,768-byte internal-SRAM ring. Foreground code drains it directly. The producer does not decide where an optical packet begins. Ring overflow is an explicit session fault. Erased or missing gates are reported as loss and invalidate the affected candidate while acquisition continues.

The streaming receiver uses a fixed local contrast detector and a fresh UART timing origin for every byte. A nine-sample local maximum, including four samples of lookahead, establishes the local background. Stop-cell validation and a completed-byte gap delimit frames; the maximum remains 136 wire bytes. An erasure or framing/overflow event invalidates the frame and requires an observed quiet boundary before accepting another. There is no alternative-packet search guided by the checksum.

Only an admitted native command that grants service, or an expired opening retry, can park acquisition. Valid ignored activity such as `0x2E` keeps reception running. Wrong-token and malformed traffic cannot refresh the native timeout or mutate saves.

The native clock and `esp_timer` remain live during reception. The dedicated FreeRTOS tick counter pauses during exclusive acquisition, and resumes before normal tick/interrupt ownership returns. FreeRTOS virtual time therefore pauses; this is an explicit contract for the quiesced application, not elapsed wall-time preservation for arbitrary background tasks. Watchdog clocks remain live. Capture progress must advance in both producer and consumer to feed the existing interrupt watchdog and a task-watchdog user; normal idle supervision returns during service and on exit.

RMT DMA holds the complete outgoing frame. A public encoder callback timestamps the end of the full copy, and synchronous transmit return bounds launch. Exact waveform duration and the completion interrupt bound the physical end. Echo exclusion uses that bound and retains later peer traffic. A bound wider than 50 microseconds fails the link.

The EEPROM image, checkpoint format, journal, durable-write ordering, native finalization, and existing save compatibility remain intact. A lost one-way `0x4E` return or `0x66` gift final instruction preserves the companion, course, identity, and uncollected Watts even if the game has already reported completion. Earlier native request handling can still update time/save state; the claim is preservation of the data whose finalization instruction was lost. There is no inferred commit or automatic operation replay.

## Defects exposed during implementation

The full-frame TX tests exposed a timestamp bracket that included the encoder's preload work. A long response could reach the peer but then trip the Walker's turnaround guard. Moving the timestamp after the complete copy bounded launch without increasing the guard. The workflow now requires both external peer completion and a clean native `PW_STICK_LINK` result after native completion.

A 5.5-second receive turn exposed the SDK's missed-tick catch-up loop: reception itself was continuous, but restoring interrupts replayed thousands of scheduler ticks and missed the service handoff deadline. Pausing only the dedicated OS counter removes that growing backlog while preserving native time and hardware watchdogs. The ten-millisecond handoff budget was not enlarged.

The stronger native completion check also exposed a harness reset that ran only one second after the game's last reply. The original completion action can still be copying 87 staged pages and updating records then; a corrupted opening acknowledgment can instead leave the native twenty-probe retry sequence active. The workflow now allows six seconds before its deliberate reset, checks the native result, and compares durable data after reboot. Native commit ordering and retries were not moved.

The initial watchdog/corruption data oracle also assumed that a registered fixture's blank own-record identity would remain blank. The existing boot repair copies the master identity there; the original status handler exports saved Watts into WalkData. The corrected oracle predicts those exact bytes where those actions occur and compares every other byte in the data region. It does not exclude the identity or Watts regions. The watchdog case also checks both identity/status mirrors and the SaveData checksums and Watts.

## Signal-model evidence

The independent workflow feeds generated optical integration samples into compiled production receiver code. All 200,062 asserted cases passed with matching source hashes, including deliberate rejection and recovery checks:

| Checks | Count |
| --- | ---: |
| All byte values, phase, transmitter clock, and pulse width | 147,456 |
| No pre-signal history | 49,152 |
| Offset and gain | 1,920 |
| Random packets of 1, 8, 32, 104, or 136 bytes | 1,200 |
| Completed-byte boundaries | 6 |
| Noise, erasure, stop, and overflow boundaries | 7 |
| Erasure positions | 256 |
| Censored dark observations | 64 |
| Wrapping timestamp | 1 |

The report also preserves negative evidence. A pulse 26 microseconds before the real start can produce a different, fully framed UART sequence; an 87-microsecond prefix can attach a byte to the packet. Native checksum validation rejects the tested corrupted sequences. The receiver does not reinterpret the signal until a checksum happens to match. Weak inputs outside the modeled envelope can produce either no frame or incorrect UART data. The six-count contrast floor is an unqualified hardware candidate.

## Production firmware workflows

The suite contains 36 scenarios: 19 UI, input, power, and storage-recovery cases, and 17 optical/native-link cases. Optical coverage includes initial provisioning, ordinary and compressed uploads, slower timing, read/write/readback, return, gifts, Walker exchange, deliberately lost final instructions, malformed requests, wrong tokens, continuous maintenance traffic, corruption, and a stalled consumer.

The initial provisioning check requires all 416 peer frames and compares the changed image, course, and trainer records after native completion and reboot. Successful workflows require both peer completion and native `result=0`, `faults=0`, and `gaps=0`. Rejection cases require diagnosed optical corruption, no unrelated transport fault, and preserved data after reboot.

The targeted 5.5-second hold run received 74 maintenance packets, supplied 110 progress feeds, and completed the following read with zero capture gaps or faults. Its maximum request-to-reply time was 17,485 microseconds and its TX end uncertainty was 10 microseconds. It also exercised six seconds of ordinary idle before manual reset. The injected consumer stall produced a genuine simulator watchdog reset (`TIMG1`, cause 8) after 897,352 microseconds, followed by a clean native exchange. These are simulator measurements, not silicon timings.

The local five-shard run began with verifier SHA-256 `36bdde30e7d69743502630509332be8334bcc5e9f161eb86bd7969ff660b4b1a`. The corrected watchdog/corruption oracle is `92a5fa29a796089d9b82c1bbe71ff83bdc65413174b40d596bb56f395cf5c8c5`. Earlier evidence remains attached to its original verifier; its source hashes and incomplete/failed results were not rewritten. Targeted reruns use the corrected verifier. The [firmware CI workflow](../../.github/workflows/check.yml) repeats all 36 scenarios with one matching build and verifier, verifies complete coverage, and also runs the macOS build/smoke checks.

## Qualification boundary

The historical IR instruction baseline remains unchanged. The steady gate loop and electrical measurement primitive are in IRAM; entry/exit helpers are outside the timed sampling interval. The replacement's instruction hash is recorded, but the timing check correctly reports `passed: false` against the old baseline. Normal release packaging rejects the image. Only the existing explicit unqualified-prerelease option permits its inventory to validate.

These checks do not establish analog margin, ESP32-S3 instruction/cache timing on silicon, DMA bus contention, or real cartridge interoperability. BPV10NF/StickS3/cartridge trials across units, lighting, alignment, and battery conditions remain necessary before calling the replacement hardware-qualified. No device was flashed and no release was published for this rebuild.
